阶段一SQL 单表取数 · 地基
递进逻辑：先学会「从一张表里取某些列、某些行」，再学会「按条件筛、按指标排、取头部」——这是取数最基础的闭环。每天 2 点推进。

递进逻辑：分组必须配合聚合才有意义；聚合出的结果想再筛，用 HAVING（不能用 WHERE，因为 WHERE 在分组前执行）。这是分析岗天天用的「各维度汇总」。

温暖の SQL 零基础互动课

不用装任何软件，不用找网页——双击这个文件就能学。每课 2 分钟。

💡 怎么用：每课先看「你想查什么」，再琢磨一句大白话，然后点「看答案」对照。 看懂了就点「这课我会了」。不用背，先看个眼熟。

第 1 课：让电脑帮你从表里查一行

场景：你想知道「中国的人口是多少」。在数据库眼里，世界各国的数据都存在一张叫 world 的表里。

用大白话想：「从 world 表里，挑出名字是中国那一行，给我看名字和人口。」

SELECT name, population FROM world WHERE name = 'China';
SELECT 后面写「我要看哪些列」；FROM 后面写「从哪张表」； WHERE 后面写「只挑满足条件的行」。这三句是 SQL 的骨架， 后面所有查询都是这三句加料。句末的 ; 是结束符号，养成习惯写上。

第 2 课：按条件筛一批（WHERE）

场景：你想看「人口超过 1 亿的国家有哪些」。

用大白话想：「从 world 表，挑人口大于 1 亿的，给我名字和人口。」

SELECT name, population FROM world WHERE population > 100000000;
WHERE 里可以写大小比较：> < = >= <=。 数字不用加引号；文字（比如国家名）才要加单引号 'China'。 这课你已经在做「筛选」了——跟你 Excel 里点筛选器是一回事，只是换了个写法。

第 3 课：排个顺序（ORDER BY）

场景：你想看「人口最多的前几个国家」。

用大白话想：「把国家按人口从多到少排，给我看前几名。」

SELECT name, population FROM world ORDER BY population DESC LIMIT 5;
ORDER BY 列名 DESC 表示「按这列从大到小排」（ASC 是从小到大）。 LIMIT 5 是「只要前 5 行」。这俩配合就是 Excel 里的「排序 + 取前 N 名」。

第 4 课：按组算汇总（GROUP BY）—— 这课最贴近你工作

场景换成你的业务：一张表里每行是一个经纪人，有「城市」和「是否续费(1/0)」两列。你想算「徐州、宿迁各自的续费率」。

💼 这就是你周报里常要算的数。Excel 里你要筛选→透视→算比例，SQL 一句话搞定。
SELECT 城市, SUM(是否续费) * 1.0 / COUNT(*) AS 续费率 FROM 经纪人表 GROUP BY 城市;
GROUP BY 城市 意思是「把同一城市的行归成一组」。 SUM(是否续费) 算出这组里续了几个，COUNT(*) 是这组总人数， 相除就是续费率。 AS 续费率 是给这列起个好懂的名字。 以后你周报里「各城市续费率」「各门店合作率」全是这个套路。
✅ 到此为止，你已经认识了 SQL 的四块积木： SELECT（看什么）· FROM（从哪来）· WHERE（挑哪些）· GROUP BY（分组算）。后面所有的查询都是这几块拼来拼去。

SQL 条件运算符速查

2026-07-27 · WHERE 后面用到的"判断工具"全在这里
💡 你为什么学：公司在优化，小城市更危险；看徐州招聘，不少岗位要 SQL+Python。学会它=多一条退路。每天练完，离「不怕变动」近一步。

一、比较运算符（两个值比大小 / 相等）

符号含义什么时候用例子（二手房业务）
=等于精确匹配某个值WHERE 城市 = '徐州'
!= 或 <>不等于排除某个值WHERE 城市 != '徐州'
>大于数值超过门槛WHERE 续费率 > 0.8
<小于数值低于门槛WHERE 合作率 < 0.5
>=大于等于含边界的"至少"WHERE 增值业绩 >= 10000
<=小于等于含边界的"至多"WHERE 开发量 <= 3
BETWEEN a AND b在 a 到 b 之间（含 a 和 b）取一段连续范围，比写 >= 和 <= 更短WHERE 经纪人开发量 BETWEEN 5 AND 10

二、逻辑运算符（把多个条件拼起来）

符号含义规则例子
AND并且所有条件都真，才留下WHERE 城市='徐州' AND 续费率 > 0.8
OR或者任意一个条件真，就留下WHERE 城市='徐州' OR 城市='宿迁'
NOT非 / 取反把条件结果反过来WHERE NOT 城市='徐州'
优先级坑：AND 比 OR 先算。写 城市='徐州' OR 城市='宿迁' AND 续费率>0.8 会先算 AND，变成"徐州的全部，或宿迁里续费率>0.8的"。要改变顺序就用括号：WHERE (城市='徐州' OR 城市='宿迁') AND 续费率>0.8。

三、成员运算符（在不在清单里）

符号含义什么时候用例子
IN (...)在清单里任意一个要匹配多个固定值，比连写 OR 干净WHERE 城市 IN ('徐州','宿迁','南京')
NOT IN (...)不在清单里排除多个固定值WHERE 门店 NOT IN ('测试店','废弃店')

四、模糊匹配（LIKE，找"包含某词"）

写法含义例子
LIKE '%词%'包含"词"WHERE 门店名 LIKE '%旗舰%'（找所有带"旗舰"的店）
LIKE '词%'以"词"开头WHERE 门店名 LIKE '徐州%'
LIKE '%词'以"词"结尾WHERE 门店名 LIKE '%店'
NOT LIKE '%词%'不包含"词"WHERE 门店名 NOT LIKE '%测试%'
通配符：% = 任意多个字符（包括0个）；_ = 任意一个字符。数据库里国家名/门店名是英文时，词也要用英文，如 LIKE '%United%'。

五、空值判断（NULL）

符号含义例子
IS NULL字段为空（没填）WHERE 续费率 IS NULL（找出漏填的）
IS NOT NULL字段不为空WHERE 增值业绩 IS NOT NULL
NULL 特殊：不能用 = NULL 判断空，必须用 IS NULL。这是新手最高频坑之一。

记忆口诀

• 比大小：= > < >= <= 跟数学一样，就多一个 BETWEEN...AND...
• 拼条件：AND 全真 / OR 一真 / NOT 取反，记不住就加括号
• 多值：IN 清单、NOT IN 除名
• 找词：LIKE 配 %，%在两边=包含
• 空值：IS NULL 不是 = NULL
• 值规则：字符串/国家名/门店名用英文单引号；数字不加引号；所有符号英文半角
今天你已经会用 =、>、IN、LIKE，这套速查帮你补全其余的。下次写 WHERE 卡壳，翻这张卡即可 👊

📒 今日复盘 · 2026-07-29

专项：ORDER BY + LIMIT + GROUP BY ｜ 零基础 SQL 单表取数练习

一、今天学了哪些

1. ORDER BY（排序）

• 单列：ORDER BY 列 DESC（降序）/ ASC（升序，可省略不写）

• 多列：只有 1 个 ORDER BY，列之间用逗号 ORDER BY 列1, 列2

• 表达式排序：ORDER BY 计算列，如 ORDER BY gdp/population DESC

2. LIMIT（取前 N 行）

• LIMIT N 截取排序后的前 N 行

• 配 ASC 取最小的前 N；配 DESC 取最大的前 N

⚠️ SQLZoo 默认引擎是 SQL Server（它用 TOP 不用 LIMIT）。想用 LIMIT 必须切到 MySQL 引擎：页面底部 Engine 下拉改成 MySQL。

3. GROUP BY（分组汇总）

• 结构：SELECT 分组列, 聚合函数 FROM 表 [WHERE ...] GROUP BY 分组列

• 聚合函数：COUNT(*)、COUNT(列)、SUM(列)、AVG(列)

SELECT continent, COUNT(*)
FROM world
GROUP BY continent;

• 执行顺序：FROM → WHERE → GROUP BY → SELECT → ORDER BY → LIMIT

二、易错点（重点记！）

1. 引擎没切 MySQL —— SQLZoo 默认 SQL Server 不认 LIMIT，会报错。底部 Engine 改 MySQL。
2. 升序拼错 —— 是 ASC，没有 sc 这种写法。
3. 多列排序写两个 ORDER BY —— 只能写 1 个，列间用逗号 ORDER BY a, b。
4. FROM 后面乱接东西 —— FROM 表 后面只跟表名。列写在 SELECT 后、条件写 WHERE，不能用逗号把列/条件塞进 FROM。
5. GROUP BY 后 SELECT 放明细列 —— 分组后一行变一组，只能放「分组列 + 聚合函数」，不能放 name 这类明细列。
6. WHERE 位置错 —— 写在 GROUP BY 前面（先筛再分组）。
7. ORDER BY 放错字段 —— 曾把 area>1000 当排序字段（那是布尔值 0/1）。筛选用 WHERE，排序字段写真正的列 area。
8. 误以为 LIMIT 能管排序 —— LIMIT 只截"前 N 行"，截得对不对全看 ORDER BY 排得对不对。
9. SQLZoo 自由练习对不上原题就显示"答案错" —— 这不代表语法错，只看你练的语法灵不灵。
10. 称呼 —— 框里写的是「SQL 语句 / SQL 查询」，不叫"句子"。

【今日知识点】

SELECT + FROM：让电脑从一张表里挑出你想看的列。

【为什么这样写 · 逻辑】

你跟人开口要东西，也是「给我看（SELECT）从哪个本子（FROM）里挑」。
SQL 之所以把这句话拆成固定结构，是因为电脑必须按确定顺序解析：它先找 FROM 指定的那张表 → 再用后面的条件筛行 → 最后按 SELECT 挑列。你写的顺序是「看啥 → 从哪」，但电脑执行的顺序是「从哪 → 挑谁 → 看啥」。
记住思考三步法：我要哪些列？从哪张表？挑哪些行？对应 SELECT / FROM / WHERE。换任何表你都会写，不用背。

【今日正式练习 · 目标 30–40 分钟】

SELECT name, population
FROM world;
SELECT name, population
FROM world
WHERE name = 'France';

【今日自测 · 做完打勾】

答案：1. 列名　2. 表名　3. WHERE → SELECT

💡 你为什么学：公司在优化，小城市更危险；看徐州招聘，不少岗位要 SQL+Python。学会它 = 多一条退路。每天练完，离「不怕变动」近一步。
📌 速查工具箱：点我打开 SQL 运算符 / 语法速查合集（练习时忘了哪个符号，随时点进来查，不用背）

【今日知识点】

用 WHERE 列 = 值 精准筛出你关心的那批数据——比如只看「徐州」的门店，或「续费率 = 已续费」的客户。这是从几万行里捞出你要的那一撮的核心开关。

【为什么这样写·逻辑】

大白话讲电脑怎么想：SELECT 告诉电脑"要哪些列"，FROM 告诉电脑"去哪张表拿"。但一张表可能有几万行（徐宿所有门店、所有经纪人），你通常只想要其中一部分。

WHERE 就是"筛选条件"——电脑会逐行扫描，只对满足条件的行放行，其余整行丢弃。等号 = 表示"完全相等匹配"：左边列的值必须恰好等于右边的值，这一行才留下。

两个坑要记住：

① 文本值必须加单引号 '徐州'，数字不用引号。电脑分不清你是写个城市名还是写段代码，加引号它才知道"这是个具体值"。

② 电脑只认精确相等，不认"差不多"。城市 = '徐州' 只留城市恰好是"徐州"的行，多一个字（"徐州市"）少一个字都不匹配。所以写条件时，值要和你表里存的一字不差。

  • 第二步：加 WHERE 等值筛选，只留徐州。

【今日知识点】

用 ORDER BY 给门店 / 城市按某个指标（续费率、合作率、开发量）排队——比如「把徐州各门店按续费率从高到低排」。这是你周报里「排名」「Top N」需求的直接工具。

【为什么这样写 · 逻辑】

ORDER BY 的作用，是告诉电脑「按哪一列来排队」。它工作在 WHERE 筛选之后——先筛出你要的数据，再对这些数据排队。理解执行顺序是关键：

FROM（找表）→ WHERE（筛行）→ SELECT（挑列）→ ORDER BY（排队）

  • 默认升序 ASC（从小到大）：不写 DESC 时，电脑按「从低到高」排。
  • 降序 DESC：排行榜要「从高到低」，必须显式加 DESC。就像排队领号，你指定按分数排、从高往低站。
  • 多列排序：ORDER BY 城市 ASC, 续费率 DESC —— 先按城市排，同一城市内再按续费率从高到低。逗号分隔，谁在前谁优先。

记住一句话：ORDER BY 永远写在 WHERE 后面，因为没筛完的数据没法排。

【今日正式练习 · 目标 30–40 分钟】

  1. 练手环境：打开 SQLZoo「SELECT from World」里的 ORDER BY 相关题目，或直接用 world 表练。
  2. 练习1（升序）：查所有国家名和人口，按人口从少到多排。
    SELECT name, population FROM world ORDER BY population;
  3. 练习2（降序）：查国家名和人口，按人口从多到少（最多的排最前）。
    SELECT name, population FROM world ORDER BY population DESC;
  4. 练习3（多列排序）：查国家名、大陆、人口，先按大陆升序、同大陆内按人口降序。
    SELECT name, continent, population FROM world ORDER BY continent, population DESC;
  5. 练习4（业务改造 · 必须自己敲）：把你周会数据的思路搬过来——假设有表 xuzhou_stores(城市, 门店, 续费率)，写一句「徐州各门店按续费率从高到低排」：
    SELECT 门店, 续费率 FROM xuzhou_stores WHERE 城市='徐州' ORDER BY 续费率 DESC;
    先 WHERE 筛城市 → 再 ORDER BY 续费率 DESC，顺序不能乱。把这句抄进 SQLZoo 的自定义框（或记在脑子里），确认自己真的理解每一步。

  1. 想看「人口最少的两个国家」（暂不加 LIMIT），ORDER BY 该怎么写？
    答：SELECT name, population FROM world ORDER BY population; —— 升序，最小的人口排最前，前两个就是最少的。
  2. ORDER BY 后面不加 DESC，默认是升序还是降序？
    答：升序（ASC，从小到大）。要降序必须写 DESC。
  3. 下面哪句顺序对？A: WHERE ... ORDER BY ...　B: ORDER BY ... WHERE ...
    答：A 对。ORDER BY 必须在 WHERE 之后，因为要先筛完再排队。

知识点 A · LIMIT —— 只取结果的前 N 行

【今日知识点】徐州续费率最高的 5 家门店，只要排在最前面的 5 名 → 用 LIMIT。

【为什么这样写·逻辑】ORDER BY 把结果排好序后，LIMIT N 告诉电脑"我只要最前面的 N 行"。它永远写在 ORDER BY 后面（执行顺序最末）。为什么需要它？排序往往是为了"看头部 / 尾部"——Top 5 门店、倒数 3 名预警，LIMIT 直接截出你要的那几行，不用肉眼翻。

SELECT 门店, 续费率 FROM xuzhou_stores ORDER BY 续费率 DESC LIMIT 5;

📝 SQLZoo 练手版：SELECT name FROM world ORDER BY population DESC LIMIT 10;（查人口最多的 10 个国家）

【练一练】把 5 改成 3，写出"人口最多的 3 个国家"的 SQL。

知识点 B · GROUP BY —— 按维度分组汇总

【今日知识点】按城市 / 门店汇总续费率、统计经纪人数量 → 用 GROUP BY。

【为什么这样写·逻辑】表里每行是一条明细（一家门店一行）。但你要的是"每个城市的平均续费率"——这需要把"同一城市的所有行打包成一组"，再对每组算平均值。GROUP BY 城市 做的正是"打包"这一步。
关键规则：分组后，SELECT 里只能出现「分组列」和「聚合结果（AVG / COUNT / SUM）」，不能写普通明细列——因为一行已经变成"一组"，明细列无法对应到单值。

SELECT 城市, AVG(续费率) AS 平均续费率, COUNT(*) AS 门店数 FROM xuzhou_stores GROUP BY 城市;

【练一练】按门店分组，统计每家门店的经纪人数量（提示：COUNT(经纪人列)）。

答案： ① 后。 ② 不能。分组后一行变一组，明细列无法对应单值，只能放分组列或聚合结果。 ③ SELECT 城市, COUNT(*) AS 门店数 FROM xuzhou_stores GROUP BY 城市 ORDER BY 门店数 DESC LIMIT 2;
